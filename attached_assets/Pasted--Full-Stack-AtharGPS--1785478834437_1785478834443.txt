أنت فريق Full-Stack + مصمم واجهات من الطراز الأول، تعمل على مستودع مشروع AtharGPS.
البنية الحالية (مهم أن تفهمها قبل أي سطر):
- Frontend: React + Vite + Tailwind، واجهة RTL ثنائية اللغة (ar + fr) عبر نظام t('key') في src/i18n/translations.js.
- مساران: واجهة عميل تحت src/pages/client/* ولوحة أدمن تحت src/pages/admin/*، مع حراس ClientRoute/AdminRoute في src/App.jsx يفحصون localStorage.
- Backend: Node.js (Express غالباً) في backend/src/ (index.js, db.js, config.js)، يتصل بـ PostgreSQL (قاعدة shgps، مستخدم shgps) وبـ Traccar API عبر TRACCAR_ADMIN_EMAIL/PASSWORD.
- Traccar: يستقبل أجهزة GPS (GT06/WanWay على 5023)، الـ Backend يوكّل (proxy) بعض طلباته.
- Nginx: يخدم dist/ على 80/443 مع شهادة Let's Encrypt، ويوكّل /api/ إلى backend.
- مكوّن DeviceSetup.jsx (تهيئة أوامر SMS) موجود ويعمل — لا تلمسه إلا إن لزم.

قواعد ذهبية — لا تُكسر تحت أي ظرف
═══════════════════════════════════════════════════════════
(1) اقرأ قبل أن تكتب. قبل أي تعديل افتح وافهم: src/App.jsx، src/pages/admin/AdminLayout.jsx، src/pages/client/Home.jsx (أو أي صفحة عميل رئيسية)، src/context/AppContext.jsx، src/api/index.js، src/i18n/translations.js، tailwind.config.js، backend/src/index.js، backend/src/db.js، backend/src/config.js، docker-compose.yml، nginx/nginx.conf. طابِق أسلوبك (ألوان، RTL، نمط البطاقات والأزرار، نظام t()) تماماً. لا تكسر صفحة قائمة.
(2) ابنِ بعد كل موجة. هذه القاعدة أهم قاعدة في المهمة كلها. بعد إنهاء كل موجة من الموجات الثلاث، شغّل npm run build وتأكد أنه ينجح بصفر أخطاء قبل أن تلمس الموجة التالية. إن فشل البناء: أصلح حتى ينجح، ولا تنتقل. لا ترفع (push) كوداً لا يبني. (تذكّر كارثة سابقة: apostrophe غير مهرّبة في الترجمات الفرنسية أسقطت البناء كله — افحص كل apostrophe في fr وتهرّبها بـ \' أو انقل السلسلة إلى "..."، وافحص العربي أيضاً).
(3) schema ذاتي الشفاء: أي عمود/جدول جديد في PostgreSQL، أضفه عبر ALTER TABLE ... ADD COLUMN IF NOT EXISTS / CREATE TABLE IF NOT EXISTS يُنفَّذ عند بدء الـ Backend (في db.js أو init)، حتى لا يحتاج تشغيل migration يدوي. وإن احتجت خطوة يدوية حتمية، ضَعْها في ملف تحت ops/ واذكرها صراحة في التقرير.
(4) لا تسأل أسئلة توضيحية. اتخذ القرارات المعمارية المعقولة بنفسك ونفّذ.

🌊 الموجة 1 — التحصين (قبل أي عميل حقيقي)
═══════════════════════════════════════════════════════════
1.1 إجبار تغيير كلمة مرور الأدمن: أضف عمود must_change_password BOOLEAN DEFAULT TRUE (schema ذاتي الشفاء). بعد تسجيل دخول أي مستخدم is_admin=true و must_change_password=true، اعرض في الواجهة modal إجبارياً (لا يُغلق، يحجب كل شيء) يطلب كلمة سر جديدة + تأكيدها بقواعد قوة (8+، حرف كبير، رقم، رمز). endpoint تغييرها يضع must_change_password=false. طبّقه على الأدمن أولاً.
1.2 Rate-limiting على تسجيل الدخول: في الـ Backend، حدّ محاولات /api/auth/login (مثلاً 5 محاولات / IP / 15 دقيقة) باستخدام express-rate-limit إن كان مثبتاً، وإلا خريطة ذاكرة بسيطة مع تنظيف دوري. ردّ 429 برسالة مترجمة عند التجاوز.
1.3 Security headers في Nginx (بلوك 443): أضف Strict-Transport-Security (max-age=31536000; includeSubDomains)، X-Frame-Options DENY، X-Content-Type-Options nosniff، Referrer-Policy strict-origin-when-cross-origin، Permissions-Policy. أضف CSP متساهلاً للخرائط فقط إن أمكن (img-src * data: blob:؛ connect-src 'self' ws: wss:؛ وإلا اترك CSP commented مع ملاحظة حتى لا تكسر Leaflet/الصور الخارجية).
1.4 نسخ احتياطي يومي تلقائي: أضف service في docker-compose.yml (مثلاً db-backup) تشغّل pg_dump لقاعدة shgps كل 24 ساعة وتحفظ الملف المضغوط في volume جديد backups_data مع إبقاء آخر 7 نسخ فقط (احذف الأقدم). لا تعتمد على cron في المضيف.
1.5 ملفات ops/ للمضيف: أنشئ مجلد ops/ فيه: ufw-setup.sh (يفتح 22,80,443,5023,5027,5029,5055 فقط ويغلق الباقي، مع تعليقات)، restore.sh (يستعيد أحدث نسخة احتياطية)، وREADME.md يشرح خطوات التشغيل اليدوي مرة واحدة. (لا تشغّلها — أنا أشغّلها).
بعد الموجة 1: npm run build يجب أن ينجح. ثم انتقل.

🌊 الموجة 2 — تجربة العميل الكاملة (ما يراه العميل ويدفع لأجله)
═══════════════════════════════════════════════════════════
افهم أولاً كيف يصل الـ Backend بمواضع الأجهزة (WebSocket موجود؟ polling Traccar؟ webhook؟) واختر الأنسب.
2.1 خريطة حيّة: في صفحة العميل الرئيسية، خريطة تعرض أجهزة العميل، تتحدّث تلقائياً (WebSocket إن كان الـ Backend يبثّ positions، وإلا polling كل 5-10 ثوانٍ). marker لكل جهاز بلون حالته، popup فيه الاسم/السرعة/آخر تحديث، وحركة انتقال ناعمة (transition) عند تغيّر الموضع.
2.2 إعادة تشغيل المسار (Playback): زر يفتح شريطاً زمنياً (من/إلى) + زر play/pause + سرعة، يجلب positions من Traccar عبر الـ Backend، ويرسم polyline يتقدّم عليه marker مع الزمن.
2.3 السور الجغرافي (Geofence): جدول geofences (id, user_id, device_id nullable, name, type circle/polygon, coords jsonb, radius, notify_enter, notify_exit) schema ذاتي الشفاء. في الواجهة: رسم دائرة/مضلّع على الخريطة وحفظه. في الـ Backend: عند استقبال position جديد، قارنه بـ geofences المستخدم، وعند اختراق أنشئ صفّاً في alerts (إن لم يكن موجوداً أنشئ جدول alerts مناسباً أو استخدم الموجود) — افحص بنية alerts الحالية أولاً.
2.4 صفحة التنبيهات: قائمة alerts مصنّفة بأيقونة ولون حسب النوع (geofence/speed/tamper/...)، زمن نسبي، تعليم كمقروء، وفلتر/بحث.
2.5 التقارير: endpoint يجمع positions لجهاز ضمن مدى زمني ويحسب: المسافة الكلية (haversine بين النقاط المتتالية)، عدد الرحلات (تجميع بفجوة توقف > N دقيقة)، مدة الحركة/التوقف، متوسط/أقصى سرعة. صفحة تعرض ملخصاً + جدول رحلات + رسم بياني بسيط للسرعة/المسافة عبر الزمن + تصدير CSV (وPDF إن وُجدت مكتبة جاهزة، وإلا CSV كافٍ).
2.6 البروفايل والإعدادات: تعديل الاسم/الهاتف/كلمة السر، اختيار اللغة، واختيار قنوات التنبيه (داخل التطبيق/بريد).
بعد الموجة 2: npm run build يجب أن ينجح. ثم انتقل.

🌊 الموجة 3 — لوحة الأدمن المتقدمة (ما تدير به عملك)

3.1 Dashboard حيّ: بطاقات إحصائية (أجهزة online/offline، عملاء نشطون، تنبيهات جديدة اليوم، أجهزة بدون إشارة > 24س) مع عدّاد count-up متحرّك عند الظهور، وخريطة مصغّرة بكل الأجهزة، وقائمة آخر التنبيهات. تستدعي endpoints (أنشئ ما يلزم في الـ Backend).

التصميم — كل صفحة قطعة معرض، لا قالب
═══════════════════════════════════════════════════════════
- خلفية طبقات/ambient هادئة: شبكة grid خافتة جداً + توهّج ناعم بلون العلامة في زاوية، لا aurora-blob تملأ الشاشة.
- حيّة وتستجيب: scroll reveals متدرّجة، hover واضح، micro-interactions على الأزرار/المبدّلات/النسخ، count-up للأرقام، خطوط الخريطة تتحرّك في playback، انتقالات ناعمة.
- تباين قوي في أحجام/أوزان الخط بين العنوان الكبير والوصف الصغير.
- زوج خطوط مميّز ومناسب للعربية/RTL: body مقروء (مثل Tajawal / IBM Plex Sans Arabic / Cairo) + display ثقيل مختلف للعناوين (مثل Reem Kufi / Changa / Lalezar). تجنّب Inter/Roboto/Arial/Geist.
- لوحة داكنة دافئة (slate/رمادي مزرق غامق) + accent أخضر زمردي مستمدّ من شعار AtharGPS (لون فعل/نجاح، لا نيون صارخ).
- تجنّب قطعياً: الخلفية السوداء الصرف + لون acid واحد، الكريم+الطيني+serif، التدرجات البنفسجية/الوردية على العناوين، glassmorphism شامل، rounded-2xl على كل شيء، صفّ ثلاث/أربع بطاقات متساوية، hero وسطي مكدّس (عنوان+وصف+زر).
- افتح كل صفحة بشيء يميّزها بصرياً (شريط حالة حيّ، معاينة بارزة، تخطيط عمودين على الديسكتوب/عمود على الجوال...).
- RTL كامل، وكل نص ظاهر مترجم في ar و fr.
